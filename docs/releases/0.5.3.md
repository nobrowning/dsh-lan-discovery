# LAN discovery 0.5.3

Network changes and offline services now appear as normal availability states instead of generic operation failures.

- Wait quietly when the selected network is absent; resume discovery when it returns.
- Mark lost service connections unavailable while retaining saved API keys and user model selection.
- Revalidate trust and credentials on explicit reconnection, replacing stale transports without duplicate providers.
- Recover from temporary Host outages; serialize repeated start/stop operations and prevent late requests after shutdown.
- Surface interrupted streams as temporary unavailability without replaying requests or tool calls. Trust, permission, authentication and protocol failures remain errors.

The portable `.tgz` bundles discovery-core 0.3.2 and runtime dependencies. Download `dsh-lan-discovery-0.5.3.tgz` and `SHA256SUMS`; install with the CLI bundled with Harness Desktop rc.3 or rc.5. Fully quit before upgrading and retain your existing profile, trust document and credentials.

Validation: 61 plugin tests, 20 core tests, empty-cache offline installation, plus physical Apple Silicon rc.5 Desktop acceptance of the runtime-identical stability candidate. The Desktop run covered real Wi-Fi loss/Ethernet failover/restoration, actual mDNS service withdrawal/reappearance, and successful HTTPS requests after reconnection. Services were local deterministic Demo APIs, not real model inference.

An explicitly configured interface address remains pinned. Returning to its network resumes discovery; automatic network migration is not included. Existing rc.5 hot-reload recovery limitations remain documented in `docs/platform-support.md`; disconnect or fully restart when needed.

中文：切网、旧网卡消失和服务离线现在显示“等待网络”或“暂不可用”，不再当作普通操作失败。已保存的凭据保留，服务恢复后需显式重连；网络、信任配置不会被自动改写。
